# ДЕНЬ × 365 — персональний фінансовий радник

Україномовний застосунок для iPhone (PWA): план дня, швидкий облік витрат, розумні порівняння «таксі чи автобус», «домашній обід чи їдальня», безпечна сума для накопичень і одна доречна порада фінансового наставника ввечері.

> Складну роботу виконує система. Користувач бачить тільки те, що важливо.

Без реєстрації, реклами, аналітики й серверів. Особисті фінансові дані зберігаються лише на твоєму пристрої.

---

## Що вміє

- **Мій день.** Витрачено, запланований бюджет, залишок, кругова шкала використання бюджету, потенціал економії → безпечно відкласти → фактично відкладено. Плаваюча кнопка «+ Витрата».
- **Швидке внесення.** Кава, смаколик, вода — одним дотиком із типовою ціною (із кнопкою «Скасувати»). Звичайна витрата — три дотики: категорія, сума на власній клавіатурі, «Зберегти».
- **План проти факту.** Шаблони «Навчання у Дніпрі», «Економний день», «Комфортний день», «Вихідний» (суми — приклад, усе редагується). Початковий план не затирається: факт показується окремим стовпцем.
- **«Як їхати вигідніше?».** Автобус, трамвай, тролейбус, метро, таксі, власне авто, пішки, комбінований маршрут. Час у дорозі, очікування, комфорт 1–5, пасажири й частка на людину, туди/назад. Для авто — пальне, паркування, знос. «Ціна комфорту» з урахуванням твоєї цінності години.
- **«Домашній обід чи їдальня?».** Дев’ять видів харчування, порівняння й потенційна різниця за 5 / 10 / 22 робочі дні. Обід із уже куплених продуктів не списується вдруге: окремо «реальний рух грошей» і «собівартість харчування».
- **Маленькі гроші — великий результат.** Мікровитрати за день, тиждень, місяць і рік, «бюджет радості» без докорів.
- **Прогнози на 30, 182 і 365 днів** у трьох сценаріях (консервативний, базовий, оптимістичний) за фактичним календарем робочих днів і періодів перебування в Дніпрі.
- **Особистий бюджет.** Доходи з датами, обов’язкові платежі, подушка, запас безпеки. Застосунок рахує, скільки можна відкласти, не зачепивши обов’язкового.
- **Фінансовий наставник.** 29 сценаріїв порад із пріоритетами, принципи за мотивами підходів Баффетта, Мангера, Грема, Богла, Лінча, Гаузела, Сеті й Даліо. Локально, без ШІ-сервісів та інтернету.
- **«А що, якби?»**, **«Ціна рішення»**, **цілі з прогнозованою датою**, **«Звички багатства»** без маніпулятивних серій.
- **Аналітика й історія.** Графіки, розподіл за категоріями, план проти факту, динаміка накопичень, порівняння транспорту й обідів, найвитратніші дні, пошук, редагування, кошик для відновлення.
- **Резервні копії.** Експорт JSON і CSV, імпорт із перевіркою структури та без дублів, автоматична попередня копія перед заміною.
- **Демо-режим** із вигаданими даними в окремій базі.
- Темна й світла теми, офлайн-робота, встановлення на екран «Додому».

## Публікація на GitHub Pages з iPhone

Усі файли лежать в одній папці, без підпапок, тож їх можна завантажити через вебінтерфейс GitHub просто з iPhone. Застосунок уже зібраний у файл `app.js`, тому GitHub Pages публікує репозиторій як є — без GitHub Actions і без жодних тек.

### 1. Створи репозиторій

1. Відкрий [github.com](https://github.com) у Safari й увійди.
2. «+» → **New repository**.
3. Назва — будь-яка, наприклад `den365`. Усі шляхи в застосунку відносні, тож він працює за будь-якою адресою.
4. Видимість: **Public** (безкоштовний GitHub Pages працює з публічними репозиторіями; особистих даних у репозиторії не буде — вони лише на телефоні).
5. **Create repository**.

### 2. Завантаж файли

1. Збережи архів у застосунку **Файли** й торкнися його — iPhone розпакує його в папку.
2. У репозиторії: **Add file → Upload files** → **choose your files**.
3. Відкрий розпаковану папку, натисни **Вибрати**, виділи всі файли → **Відкрити**.
4. Внизу — **Commit changes**.

GitHub приймає до 100 файлів за раз — в архіві їх менше. Файли з крапкою на початку назви (`.gitignore`, `.nojekyll`) iPhone може не показувати — це нормально, для роботи вони не обов’язкові.

**З комп’ютера:** перетягни всі файли з розпакованої папки на сторінку **Upload files** і натисни **Commit changes**. Або через git: `git add . && git commit -m "ДЕНЬ × 365" && git push`.

### 3. Увімкни GitHub Pages

1. **Settings → Pages** (у мобільній версії Settings — у меню репозиторію).
2. **Build and deployment → Source:** **Deploy from a branch**.
3. **Branch:** `main`, папка `/ (root)` → **Save**.

### 4. Дочекайся публікації

За 1–2 хвилини на вкладці **Actions** з’явиться зелений запуск «pages build and deployment» — GitHub створює його сам, налаштовувати нічого не треба. Адреса застосунку — вгорі сторінки **Settings → Pages**:

```
https://ТВІЙ-ЛОГІН.github.io/НАЗВА-РЕПОЗИТОРІЮ/
```

### 5. Встанови на iPhone

1. Відкрий адресу застосунку саме в **Safari**.
2. Кнопка **Поділитися** (квадрат зі стрілкою) → **На початковий екран** → **Додати**.
3. Запускай із іконки — застосунок відкриється на весь екран, як звичайний, і працюватиме без інтернету після першого завантаження.

> Установлення на екран «Додому» важливе й для збереження даних: дані сайтів, які давно не відкривали в Safari, браузер може видаляти, а встановлені вебзастосунки під це правило не потрапляють.

### Якщо не працює

- **Вічна заставка або «Застосунок не завантажився»** — у репозиторії немає `app.js` або він не з того архіву. Завантаж `app.js`, `index.html` і `sw.js` з архіву разом, одним комітом.
- **Сторінка 404** — перевір крок 3: Deploy from a branch → `main` → `/ (root)`. Після зміни налаштувань зачекай 1–2 хвилини.
- **Після оновлення досі стара версія** — GitHub і Safari можуть до 10 хвилин віддавати збережену копію сторінки. Зачекай і онови сторінку; у встановленому застосунку з’явиться банер «Доступна нова версія».
- **«Застосунок не запустився» з текстом помилки** — зроби знімок екрана: у ньому є все потрібне, щоб знайти причину.

### Необов’язково: публікація через GitHub Actions

Для роботи з комп’ютера, якщо хочеш, щоб перед кожною публікацією автоматично проходили тести й свіже збирання: поклади `deploy.yml` за шляхом `.github/workflows/deploy.yml` і в **Settings → Pages** обери **Source: GitHub Actions**. Основному шляху це не потрібно; без цього кроку файл `deploy.yml` у корені GitHub просто ігнорує.

## Резервні копії

**Зберегти:** Налаштування → Резервні копії → **Резервна копія (JSON)**. На iPhone відкриється меню «Поділитися» → **Зберегти у Файли** (iCloud Drive чи «На iPhone»). Там само є експорт **Операції (CSV)** і **Підсумки днів (CSV)** для Excel чи Таблиць (роздільник «;», копійки через кому).

**Відновити:** Налаштування → Резервні копії → **Відновити з файлу JSON** → обери файл. Застосунок перевірить структуру й покаже, скільки нових записів і скільки повторів. Далі:

- **Обʼєднати** — додати нове, повтори пропустити (за ідентифікатором і «відбитком» запису), для того самого запису залишити новішу версію;
- **Замінити** — повністю замінити дані копією.

Перед будь-яким імпортом чи скиданням поточні дані автоматично зберігаються як **попередня копія** — її можна повернути кнопкою «Повернути попередню копію».

**Рекомендація:** роби копію щотижня й обов’язково — перед очищенням Safari, зміною телефону чи перевстановленням.

## Оновлення застосунку без втрати даних

1. Завантаж нові файли з архіву (**Add file → Upload files**; файли з тими самими назвами GitHub перезапише) → **Commit changes**. Для роботи сайту головні три — `app.js`, `index.html` і `sw.js`: завантажуй їх завжди разом.
2. За 1–2 хвилини GitHub Pages опублікує нову версію.
3. Наступного разу, коли відкриєш застосунок, угорі з’явиться «Доступна нова версія» → **Оновити**.

Дані при цьому не зникають: вони зберігаються в IndexedDB на пристрої, а оновлюються лише файли застосунку. Для спокою — зроби резервну копію перед великим оновленням.

---

## Де зберігаються дані — важливо

- Усі особисті фінансові дані зберігаються **лише локально** на пристрої в IndexedDB браузера (якщо вона недоступна — у localStorage). У GitHub не потрапляє нічого, крім коду застосунку.
- Дані **не синхронізуються** між пристроями автоматично. Щоб перенести — експорт JSON на одному пристрої й імпорт на іншому.
- Дані **можна втратити**, якщо очистити дані Safari («Налаштування → Safari → Очистити історію й дані»), видалити іконку застосунку з екрана «Додому» або скинути телефон. Тому потрібні регулярні резервні копії.
- Застосунок не надсилає дані стороннім сервісам: немає аналітики, реклами, трекерів і платних API.

## Як рахуються гроші

Фінансова точність важливіша за красиві графіки.

1. **Копійки.** Усі суми зберігаються в цілих копійках; показуються в гривнях. 0,1 + 0,2 тут завжди 0,3.
2. **Типи операцій не змішуються:** витрата, дохід, повернення, переказ у накопичення, зняття з накопичень, переказ між своїми рахунками, собівартість уже купленого.
3. **Без подвійного обліку продуктів.** Обід із куплених раніше продуктів записується як собівартість (не рух грошей). Показники: «реальний рух грошей на їжу» і «собівартість харчування».
4. **Невитрачене ≠ заощаджене.** Три різні числа: потенціал економії відносно плану → безпечно відкласти → фактично відкладено (лише після переказу, який фіксуєш кнопкою «Відкласти гроші»; гроші з банку застосунок не списує).
5. **Безпечна сума:** доступні кошти − обов’язкові платежі до наступного доходу − щоденні потреби на ці дні − залишок плану на сьогодні − запас безпеки. Якщо є план — не більше за сьогоднішню економію. Якщо на обов’язкове бракує — відкладати не радить.
6. **Майбутні доходи** не вважаються доступними, доки не надійшли. Якщо доходів не вказано, резерв рахується на 30 днів наперед.
7. **Обов’язкові платежі** (оренда, кредити) не псують денний бюджет: резервуються окремо, сплачені — позначаються автоматично.
8. **Повернення** — окрема коригувальна операція. Прив’язане до покупки — виправляє день і категорію тієї покупки.
9. **Пропущений день ≠ день без витрат.** День без записів — «немає даних» і не тягне середні вниз. Завершений день без витрат — справжній нуль.
10. **Дати** — за київським часом (Europe/Kyiv) незалежно від налаштувань пристрою.
11. **Редагування** будь-якого запису (зокрема в завершеному дні) одразу перераховує всі підсумки й пораду дня.
12. **Від’ємних витрат** у звичайному введенні немає; суми перевіряються.

## Прогнози

- **Консервативний:** економія повторюється лише в робочі дні; перевитрати вихідних враховуються, їхня економія — ні.
- **Базовий:** медіана твоїх днів окремо для робочих і вихідних.
- **Оптимістичний:** ти тримаєшся плану на 20 відсоткових пунктів частіше.

Прогноз з’являється після 5 днів із планом і записами (з них 3 робочі). До того — лише умовна ілюстрація: «якщо повторювати цю економію в робочі дні». Один день ніколи не множиться на 365 як «точний прогноз». Можна рахувати лише дні перебування в Дніпрі.

## Фінансовий наставник

Після кнопки «Завершити день» застосунок обирає **одну** пораду з 29 сценаріїв:

1. **Стійкість** — дефіцит на обов’язкові платежі, борги з малим запасом, перевитрати (через необов’язкове чи через необхідне), велика непередбачена витрата.
2. **Найвагоміше рішення дня** — таксі понад план чи виправдане цінністю часу, спільна поїздка авто, домашній обід, їжа поза домом, мікровитрати понад чи в межах бюджету радості, продукти, повернення.
3. **Наступний крок і система** — відкласти економію, налаштувати бюджет, стабільні перекази, ціль майже досягнута, план систематично занижений чи завищений, день без плану, день без витрат, пропуски записів.
4. **Обережні поради**, коли даних мало.

У межах рівня перемагає порада з найбільшим впливом у гривнях. Картка: автор, принцип, чому саме сьогодні, крок на завтра, ефект у гривнях (якщо його можна обґрунтовано порахувати). Формулювання — «за мотивами підходу», а не цитати. Це не індивідуальна інвестиційна консультація.

## Технічна архітектура

- **TypeScript** у суворому режимі; інтерфейс — TSX із власним мінімальним рендером (без React).
- **Без сторонніх бібліотек у браузері:** власні SVG-графіки, власний набір значків, IndexedDB напряму, власний сервіс-воркер.
- **Тести** — вбудований тест-раннер Node.js (`node:test`).
- **Збирання** — компілятор TypeScript + невеликий скрипт `build.mjs`: усі модулі складаються в один файл `app.js` (усередині — крихітний завантажувач модулів), версія за вмістом проставляється в `index.html` і `sw.js`. Зібрані файли лежать у репозиторії, тож GitHub Pages публікує його як є. Єдина залежність розробки — `typescript`.
- **Сторож запуску** в `index.html`: якщо застосунок не стартує (файл не завантажився чи сталася помилка), замість вічної заставки з’являється пояснення й кнопка «Оновити сторінку».
- **Без маршрутизатора з адресами сторінок:** вкладки працюють через `#` в адресі, тож перезавантаження ніколи не дає 404 на GitHub Pages.

Чому так, а не React + Vite + Tailwind + Recharts:

- плоска структура без тек — можна вивантажити з iPhone;
- нуль залежностей у браузері: швидкий старт на телефоні, надійна офлайн-робота, жодних оновлень бібліотек, що можуть зламати збирання;
- одна залежність на етапі збирання, а готовий `app.js` уже в репозиторії — сайт не залежить від збирання на сервері, а оновлення з iPhone — це три файли;
- повний контроль над iOS-деталями: безпечні зони екрана, розмиття панелі, системний шрифт, анімації з урахуванням «Зменшення руху».

## Розробка на комп’ютері

Потрібен Node.js 22.18 або новіший.

```bash
npm ci            # встановити TypeScript
npm test          # перевірка типів + тести фінансової логіки
npm run build     # перевірка типів і збирання app.js; оновлює index.html і sw.js
npm run preview   # відкрити http://localhost:4173/den365/
```

Після зміни будь-якого `.ts` / `.tsx` виконай `npm run build` і додай у коміт `app.js`, `index.html` і `sw.js` разом зі зміненими вихідними файлами — саме їх публікує GitHub Pages.

### Що покривають тести

Додавання витрат у копійках · перевищення денного бюджету · відсутність доходів · брак коштів на обов’язкові платежі (і пріоритет поради про стійкість) · порівняння таксі й автобуса · вартість поїздки автомобілем і частка пасажирів · домашній обід без подвійного списання · прогноз лише для робочих днів · різниця між пропущеним днем і днем без витрат · повернення грошей · переказ у накопичення · відновлення резервної копії й імпорт без дублів · вибір однієї доречної поради · дати за Europe/Kyiv (зокрема літній час і інший пояс пристрою) · перерахунок після редагування, видалення й відновлення · демо-день (650 → 460 → 190 грн).

## Демо-режим

Налаштування → **Демо-режим**. Вигадані дані зберігаються в окремій базі й не змішуються з особистою історією; вимкнення повертає твої дані. Демо-день: план 650 грн, фактично 460 грн (автобус 60, кава 60, продукти 280, смаколики 60; домашній обід 65 грн із уже куплених продуктів не списується вдруге), різниця 190 грн. Прогнози на основі 190 грн показуються, але в накопичення автоматично не записуються.
